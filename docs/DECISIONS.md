# Decisions

One line of reasoning per decision. Newest at the bottom.

- **D-001 Name: Showmark.** "Haazir" was hard to say for a global jury. Showmark means the mark you get for showing up and echoes "hallmark", the official stamp that certifies something is genuine, which matches the passport-and-ink design. Collision checks on 19 Nov 2026: no product or crypto project of that name, `showmark` and `@showmark/*` free on npm, `showmark.qie` free on the Zone contract. Rejected: Countersign (e-signature SaaS and taken npm scope), Muster (existing attendance app), Stamped (reviews platform), Hereby (popular npm tool), Turnout (event analytics company), Rollcall (newspaper).
- **D-002 EVM target: shanghai.** PUSH0 executed on mainnet and testnet via eth_call; TSTORE (0x5d) is an invalid opcode on mainnet, so no Cancun features and no transient-storage reentrancy guard.
- **D-003 Oracle staleness is a constructor parameter.** The QIE/USDT feed is deviation-triggered (7 rounds inside 50 minutes, then a 23 hour gap), so the limit is chosen at deploy from measured history and a stale price defers settlement instead of failing a check-in.
- **D-004 Check-in and settlement are separate transactions.** The registry never calls the vault, so a campaign problem can never block a check-in (invariant 2). The relayer sends settlement right behind the check-in with the next nonce, so both usually land in the same block.
- **D-005 Event metadata lives in event logs, not a database.** Name, venue and city are emitted as a JSON string in `EventCreated`/`EventMetadataUpdated`. At 1 gwei this costs fractions of a cent and keeps every public page derivable from the chain.
- **D-006 Attendee identity is a pass key, linked once to a wallet.** The app holds a local key that signs check-ins without any wallet popup, which is what makes scan-to-stamp under 10 seconds possible. Linking requires signatures from both the pass and the wallet and is one-to-one, so one QIE ID holder cannot farm QIE-ID-gated campaigns with many passes.
- **D-007 QIE ID gating is checked at settlement.** A gated campaign pays only once the pass is linked to a wallet holding a QIE ID; settlement is permissionless and retryable until the grace period ends, so linking later still pays out.
- **D-008 No wagmi.** QIE Wallet needs custom EIP-6963 handling (isMetaMask is true, no disconnect event) and the check-in route has a 170 kB budget, so the app uses viem directly with a small EIP-6963 store.
- **D-009 Pass keys can be derived from a wallet signature.** A wallet-first user signs a fixed message and the pass key is the hash of that signature, so the same pass can be recreated on a new phone. Used only after signing twice and getting identical signatures, since not every wallet signs deterministically. Guests get a random pass.
- **D-010 Keys generated locally by the lead.** The goal says to decide without asking, so the deployer and relayer keys were created with `cast wallet new` straight into the gitignored `.env.local`, printing only addresses. Ownership of every contract moves to a Safe, so the deployer key holds no lasting power.
- **D-011 Hosting on the existing Vercel team (adwaitbytes-projects), project `showmark`, root `apps/web`.** It is the account already logged in on this machine; free Marketplace tiers for Neon and Upstash.
- **D-012 Public repo under the logged-in GitHub account (23f2000979/showmark).** The team org is not known yet; the repo can be transferred to the team org later without losing history.
- **D-013 Next.js 16.4, React 19.3, Tailwind 4.3, viem 2.58, zod 4.6, Drizzle 0.45, OpenZeppelin 5.6.1, solc 0.8.38.** Current stable releases from the registries on 19 Nov 2026. TypeScript stays on 5.9 because that is what Next 16 ships with; TypeScript 7 is too new to trust for the build.
- **D-014 Testnet funding through Yathu's QIE Wallet.** The faucet requires a connected browser wallet, and importing a key into a web page breaks the secrets rule. Until testnet QIE arrives, contracts are proven on anvil with chain id 1983.
- **D-015 OpenZeppelin pinned to v5.1.0 (workstream A).** Later 5.x releases pull in Cancun-only code paths, and QIE mainnet rejects TSTORE, so 5.1.0 is the newest release that compiles cleanly for shanghai.
- **D-016 Submission category chosen by visible label.** The live form stores "Consumer Apps & Social" as `gaming` and "Commerce & Real World" as `social` (read from its bundle on 19 Nov), so we pick by label and check the dashboard after submitting.
- **D-017 Judges' desk campaign uses fixed token pricing, no QIE ID requirement, mode 1.** A stale oracle must never delay a judge's payout during the live demo.
- **D-018 QIE ID gate reads the free name registry, not Zone balance.** Phase 0 showed Zone balances are not a reliable signal and names live in registry 0x1D69...f62e. The vault calls a small `QieIdCheck` adapter (`userDomain(wallet)` non-empty) through a staticcall that can never revert settlement. Trust assumption, stated in SECURITY.md: that registry is an upgradeable proxy owned by a QIE EOA.
- **D-019 Oracle staleness limit 48 hours; fixed token pricing is the default.** The QIE/USDT feed is pushed by one EOA with a measured p99 gap of 29.5 h and max 50.1 h. A 48 h limit would have deferred settlement 0.6 percent of the time. The sponsor form defaults to a fixed QIE amount and shows USD only as an estimate.
- **D-020 Native QIE is the default campaign token.** The only QUSDC pool holds about 4,631 QUSDC; buying 500 QUSDC costs about 11 percent in price impact, so QUSDC is offered for sponsors who already hold it.
- **D-021 Mobile wallet linking goes through WalletConnect later.** QIE Wallet mobile is in the WalletConnect registry with no evidence of an in-app browser. Check-in itself needs no wallet, so Tier 1 is unaffected; linking on mobile needs a Reown project id (NEEDS item) and a phone test.
- **D-022 Pitch names the closest overlap.** Northeside HostRewards pays online league hosts per returning player from operator Merkle roots. Showmark differs in physical presence proven by door signatures, per-presence on-chain settlement, and attendee payouts.
- **D-023 Build from the workspace root.** The web app imports the built `@showmark/sdk` and `@showmark/mcp`, so Vercel runs `pnpm --filter "web..." build`, which builds dependencies first in order.
- **D-024 MCP server stays on @modelcontextprotocol/sdk 1.32.2.** It is the current release of the v1 line the docs still cover; moving to the separate v2 package is not worth the risk this week.
- **D-025 Indexer sweep every two minutes with Vercel Cron.** The team is on Vercel Pro, so a cron can call `/api/cron/sync` often; it indexes, drains the relay queue and retries settlements that can now pay. Pages also catch up on read.
- **D-026 Per-IP relay limit 120 per minute in production.** A venue's Wi-Fi or a carrier NAT puts a whole room behind one address; the per-pass limit of 3 per minute and the one-presence-per-event rule do the real protection.
- **D-027 Correction to D-013 and D-015: OpenZeppelin v5.1.0.** Releases 5.2 to 5.7 use the Cancun-only `mcopy` in code paths we reach (EIP712, Strings, SignatureChecker, ERC1155 arrays). v5.1.0 is the newest release with no mcopy, tstore or tload in any file we compile.
- **D-028 Web ABIs are generated from the Foundry exports** by `scripts/sync-web-abi.mjs`, so the app, the SDK and the contracts cannot drift. The indexer's exhaustive event switch caught the admin events the hand-written ABI had missed.
- **D-029 Unlinked accounts withdraw only for themselves.** Anyone may trigger a withdrawal for a linked pass because the money can only go to its wallet; for an unlinked address only that address may call, so nobody can push rewards onto a gasless browser key.
- **D-030 Repo moved to github.com/Adwaitbytes/showmark** (supersedes D-012). Yathu asked to use only the Adwaitbytes account, which also owns the Vercel team. `scripts/push.sh` pushes with that account's token after a secret scan.
- **D-031 Audit C-01 fixed with per-rotation ticket keys.** A door pass in calldata was reusable by anyone for its whole validity window. Now each 15 s rotation authorizes a throwaway ticket key whose private key exists only in the QR, and every mode 1 check-in carries that key's signature over the attendee. Rejected alternative: single-block passes, which would refuse honest attendees scanning the same code seconds apart.
- **D-032 Check-in JavaScript budget is counted per route, on top of the shared framework.** The brief's 170 kB cap was set before we knew Next 16 and React 19 ship 143 kB shared by every page. The check-in route's own code is 57 kB, first paint loads 178 kB in total, and on throttled 4G with a 4x slower CPU the largest paint lands at 0.85 to 1.1 s, well inside the 2.5 s target. Cutting the shared runtime would mean dropping the App Router, which costs more than it saves.
- **D-033 Upstash Redis provisioned through the Vercel Marketplace** (free plan, store showmark-kv). Terms were accepted in the browser after Yathu gave blanket permission on 19 Nov. The backend reads the `KV_REST_API_*` names directly.
- **D-034 Open-to-bonded campaigns are native QIE only (audit M-02).** A QIE bond cannot bound a QUSDC payout without pricing it, so the vault caps cumulative open payouts per organizer by its QIE bond and refuses open ERC-20 campaigns. QUSDC sponsors approve events explicitly.
- **D-035 Fix re-review N-01 and N-02 instead of shipping known limitations.** Organizers opt in to each open campaign and exposure is released after a clean grace period (N-01); a challenge locks only what that campaign paid the organizer and needs a refundable deposit (N-02). Contracts are immutable, so it is cheaper to fix now than to explain later.
- **D-036 Ticket keys travel in the URL fragment (audit N-03).** Browsers never send the fragment, so the key stays out of Vercel logs; the attendee page reads it on the client and clears it from history.
- **D-037 pnpm allows esbuild's build script** (`allowBuilds` in pnpm-workspace.yaml). pnpm 12 refuses a frozen install with ignored build scripts, which failed the first Vercel build.
- **D-038 Bond challenges become claims sized by the campaign's bonded exposure (second re-review N2-01, N2-02).** A lock snapshotted from free stake let a sock-puppet challenge shield the stake from an honest one, and a 1-unit token campaign could freeze a whole bond. Each challenge now claims exactly what its campaign paid through the bond, unbonding holds back the sum of open claims, and only opted-in native QIE open campaigns can challenge.
- **D-039 Fix the third re-review's two Lows before mainnet.** The auditor gave a go, but the contracts are immutable and mainnet is still waiting on funds, so a live `refreshClaim` (N3-01) and a 7 day review period before exposure release (N3-02) cost one more short cycle and remove two caveats from the sponsor guide.
- **D-040 The Judges' desk runs a server-side door.** A judge must be able to check in from their own phone at any time during demo week without someone keeping a laptop open, so `/judges` fetches a pass signed every 15 s by a server-held door key for one dedicated event with a team-funded pool. It is mode 1 and labelled on the page as run by the team. Testnet event 2 now; the same setup is recreated on mainnet.
- **D-041 Section labels are sentence case in ink-soft everywhere.** QA found organizer pages using uppercase grey and sponsor pages vermilion; the copy rules require sentence case and the brief asks for one vermilion accent used sparingly, so vermilion is kept for the single primary action and the check-in stamp.
- **D-042 Mainnet protocol fee 1 percent, paid to the protocol Safe.** It is the business model judges will ask about, it is far below the 5 percent hard cap, and it is snapshotted per campaign so it can never change on a live campaign. Team-funded pools pay it too, so the number on /traction is honest.
- **D-043 One script launches mainnet** (`scripts/mainnet-launch.sh`): preflight (Safe has code, balances, tests), deploy with the Safe as pending owner, verify, write the Safe Transaction Builder batch for `acceptOwnership`, repoint Vercel, clear the testnet index, push. Switching to mainnet removes testnet-only address overrides and the testnet Judges' desk settings.
